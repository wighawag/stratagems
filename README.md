# 👾🌍 An Autonomous World In Constant Evolution

[Stratagems](https://stratagems.world) is a game where players are actual gods. They are literaly the one creating the world and its inhabitants.

Stratagems is an [Autonomous World](https://0xparc.org/blog/autonomous-worlds) and is thus permission-less and persistent. Its rules are immutable yet it is fully composable and as a community players can bring new dimensions to the world all permissionlessly.

We expand on that idea in our latest essay: ["Natural Compoability in Autonomous Worlds"](https://etherplay.io/blog/natural-composability/).

## ♟️ What is stratagems exactly ?

<img align="right" style="width:200px" src="docs/public/icon.png">
Stratagems is a world created by players and anyone can join at any time. Players use a specific set of factions to compete for control of the world. Alliances and betrayal are part of the arsenal as factions mixes around the world thus created.

Stratagems is thus first and foremost a social game. Its main inspiration is [Conquest.eth](https://conquest.game) who successfully created a deeply social game out of simple mechanics.

Stratagems explores this further by having even simpler rules. It also reduces the gas cost to a minimum by spreading the actions over a week. It works because most of the game plays out in the conversations and strategies happening among the players.

While maximally on-chain, Stratagems scales with players by offering compelling off-chain gameplay thanks to its associated social complexity.

## 🎮 How do you play ?

Players participate in the game by depositing ETH (ratio to be defined) to place a new piece of land on the endless sea. They specify its location and faction.

By doing so, they risk the associated ETH but also get a chance to potentially capture the same (and more) from other players.

## 💻 Install

> We are assuming here that you have [nodejs](https://nodejs.org/en) and [pnpm](https://pnpm.io/) installed
>
> We also recommend to install [zellij](https://zellij.dev/)

1. Clone the repository

   > Before cloning you will need to have [git LFS (Large File Storage)](https://git-lfs.com/) installed

   ```
   git clone https://github.com/wighawag/stratagems.git
   cd stratagems
   ```

   Then, ensure the LFS hooks are present:

   ```sh
   git lfs install
   ```

   > If you installed git lfs after already cloning the repo, you will also need to execute the following:

   ```sh
   git lfs pull
   ```

2. Install dependencies

   ```bash
   pnpm i
   ```

3. Then Assuming you have [zellij](https://zellij.dev/) installed

   ```bash
   pnpm start
   ```

   **And you are ready to go!**

> **Note** If you do not have [zellij](https://zellij.dev/) (on windows for example) you can use [wezterm](https://wezfurlong.org/wezterm/index.html)
>
> ```bash
> pnpm start:wezterm
> ```
>
> Or you can also launch each component in their own process
>
> ```bash
> pnpm local_node
> ```
>
> ```bash
> pnpm contracts:compile:watch
> ```
>
> ```bash
> pnpm contracts:deploy:watch
> ```
>
> ```bash
> pnpm indexer:dev
> ```
>
> ```bash
> pnpm web:dev
> ```

## 👾 Play

Just navigate to the url mentioned in the console. If you have no other thing running, it should be [http://localhost:5173/]()

## Deploying to a network

Just execute the following

```bash
pnpm contracts:deploy:prepare <network>
```

and it will ask you few questions and get your .env.local setup with the var needed to deploy on the network of your choice.

You just need to have a endpoint url and mnemonic ready for it.

You can of course configure it manually with more option if you need

Then you can deploy your contract

```bash
pnpm contracts:deploy <network>
```

And you can verify the contract

- on etherscan:

```bash
pnpm contracts:verify <network> etherscan
```

- using sourcify:

```bash
pnpm contracts:verify <network> sourcify
```

for etherscan if the network is not supported by default (no endpoint), you can provide your own:

```bash
pnpm contracts:verify <network> etherscan --endpoint <api endpoint url>
```

## On an ethereum-lan-node box

stratagems' tables (games for a fixed set of players, created from `/lobby/` and joined by link) and its offline world (hotseat and AI seats, a chain inside the tab) can be played on a LAN with no internet, on a box running [ethereum-lan-node](https://github.com/wighawag/ethereum-lan-node): geth in dev mode (chain 19216801, a block every 2 s), a faucet on port 34010, everything over plain `http://`. The persistent world is deployed there too, with its day-long cycles.

### The package

```bash
nix build git+file://$PWD#lan
```

builds the game as one of the box's games, with no network, by ethereum-lan-node's `lib.mkRockethGame` (`flake.nix`, the template tree's; what is stratagems' own is the `"lan"` field of the root `package.json`: its pnpm dependencies' hash, its solc, its description, and its `preWebBuild`, which exports the addresses to the indexer too and builds `common`, the indexer and its processor bundle before the web app): the contracts compiled with the official solc 0.8.24 WASM build, deployed into a throwaway chain with the box's chain id to learn their addresses, the web app built against them (`web/.env.lan`), and the indexer's processor bundle beside it. The result holds:

- `web/`, the static site, served by the box with `/404.html` as its fallback;
- `bin/stratagems-deploy`, which replays the recorded deploy on the box's chain (24 contracts and 4 setup calls, every one CREATE2 or guarded): it refuses another chain id or another block 0, sends nothing on a second run, and so runs on every boot and after a reset;
- `passthru.lan`, the title and description the box's page shows.

After any change to `pnpm-lock.yaml`, recompute `pnpmDepsHash`: set it to `sha256-AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA=` and run `nix build git+file://$PWD#lan.pnpmDeps`, which fails with the right value (a build that passes proves nothing: Nix trusts a hash it has seen). The deploys are deterministic only on `lan` (the `deterministic` tag in `contracts/rocketh/config.ts`): every other environment keeps the addresses it has. No contract test checks that the `lan` deploy stays replayable: `nix build` refuses a deploy that is not, and names the transaction, so build it after changing a deploy script.

To rehearse it on this machine, without the box: `bash scripts/rehearse-lan.sh e2e/tests/faucet.e2e.ts e2e/tests/stratagems-hotseat.e2e.ts e2e/tests/stratagems-offline-ai.e2e.ts`. It starts geth from the box's genesis, the package's deploy (twice), the box's faucet and caddy on this machine's LAN address (ports 8545, 34010 and 28600 there, which must be free), and runs those suites in a browser that can reach nothing else: two empty burners funded by the faucet at a table, a cycle played, and the offline world in the same insecure context.

### On the box (my-boxes)

The box's configuration takes the package as a flake input and names it as a game, after `conquest`:

```nix
# inputs (not following the fleet's nixpkgs)
stratagems.url = "github:wighawag/stratagems";

# the box
services.ethereumLanNode.games.stratagems = {
  package = inputs.stratagems.packages.x86_64-linux.lan;
  webPort = 8002;
};
```

with port 8002 opened by its surface check, and the box's ethereum-lan-node recent enough for the faucet's `corsOrigins` (538bd15, below); the package itself is built by the ethereum-lan-node stratagems' own `flake.lock` names, whatever the box runs.

### By hand, from a laptop

1. Point the `lan` environment at the box, in `contracts/.env.local` (the defaults in `contracts/.env` are `http://ethereum.local:8545` and the box's public `test ... junk` mnemonic, which its genesis funds):

   ```bash
   ETH_NODE_URI_lan="http://ethereum.lan:8545"   # on the box's hotspot; or the box's address on another network
   ```

2. Deploy and export, then build:

   ```bash
   pnpm contracts:deploy lan
   pnpm --filter ./web build lan
   ```

   The addresses the build embeds are the same on every box and after every reset of its chain. `pnpm build lan` would also try to pre-index the chain into the build; a box's chain starts empty, so building the web app alone is enough and the indexer folds the chain in the browser.

3. Serve `web/build` from the box on a port of its own. Every URL in the `lan` build is same-host (`web/.env.lan`: the node at `//:8545`, the faucet at `//:34010`), so one build works on the hotspot address, on a venue's network and by name.

**After a reset of the box's chain, delete `contracts/deployments/lan` before deploying again.** The genesis is the same, so rocketh cannot tell the chain was reset and reuses records whose contracts no longer exist. The package's deploy keeps its records in the box's state directory, which a reset wipes, so this is only for a deploy from a laptop.

### What a box needs

Found by the rehearsals of steps L2 and L3:

- **The faucet must allow other origins** (`CORS_ORIGINS`): a game is served on another port than the faucet, so it is another origin, and without it the app's "Get ETH" fails with "Failed to fetch". ethereum-lan-node sets it from its `faucet.corsOrigins` option, `*` by default.
- **geth mines no transaction whose tip is below 1,000,000 wei**, and will not be configured lower. On an idle chain every fee-history reward is zero, so the app takes the node's own `eth_maxPriorityFeePerGas` as the least tip it sends.
- **The records must name the box's genesis**: an indexer refuses a node whose block 0 is not the one its records name, so the package's build gives them the box's genesis hash, and its deploy checks the box's block 0 against it.
- **It is not a secure context**: no `crypto.subtle`, no `crypto.randomUUID`, no service worker, no `navigator.locks`. The app works without them, the offline world included: without `navigator.locks` its one-tab claim is not guarded, rather than refused.
- **One faucet claim is one stake**: the chain is priced at 1 gwei (the box's genesis base fee), so a stake forwards about 0.717 ETH to the browser's key (step L2's measure at that price), of the claim's 1 ETH.
