# `with/fuzd-pixi-indexer`

`with/fuzd`, `with/pixi-js` and `with/indexer`, merged: the node for a game that wants fuzd's automatic reveal, the pixi host AND its state from its own etherfold processor. stratagems is that game. It replaced `with/fuzd-pixi` (`with/fuzd` and `with/pixi-js`), which stratagems alone stemmed from, when stratagems' indexer hosting moved into the template tree (its step X1, PX6 of its plan).

```
template-commit-reveal@main
├─ with/pixi-js
├─ with/nft-identity
├─ with/fuzd
├─ with/indexer
├─ with/all                [with/pixi-js, with/nft-identity]          reveal-or-die, bomber-world
└─ with/fuzd-pixi-indexer  [with/fuzd, with/pixi-js, with/indexer]    ← here; stratagems stems from it
```

**It carries no code of its own**, the rule `README.all.md` gives an integration node: its diff against the union of its parents is empty, but for `web/package.json` (every parent's dependency lines) and `pnpm-lock.yaml` (regenerated by `pnpm install`). So this file is the node's one addition. Its history starts from `with/fuzd-pixi`'s, which is exactly `with/fuzd` merged with `with/pixi-js`.

**Cascade ritual**: `main` into `with/fuzd`, `with/pixi-js` and `with/indexer` first, then all three into this node, in any order; a conflict here should only ever be the lockfile, resolved by taking either side and running `pnpm install`.
