# `with/fuzd-pixi`

`with/fuzd` and `with/pixi-js`, merged: the node for a game that wants fuzd's automatic reveal AND the pixi host. It exists because no other node has both (`with/all` is `with/pixi-js` with `with/nft-identity`, and stems reveal-or-die and bomber-world, which do not use fuzd), and because the alternatives were worse: fuzd added to `with/all` would bring fuzd to games that do not want it and the identity axis to a game that does not want that, and pixi copied into a game is a divergence by copy, every pixi fix then ported by hand.

```
template-commit-reveal@main
├─ with/pixi-js
├─ with/nft-identity
├─ with/fuzd
├─ with/all            [with/pixi-js, with/nft-identity]   reveal-or-die, bomber-world
└─ with/fuzd-pixi      [with/fuzd, with/pixi-js]           ← here; stratagems stems from it
```

**It carries no code of its own**, the rule `README.all.md` gives an integration node: its diff against the union of its parents is empty. Measured on creation (2026-10-31, in stratagems' step 9): the 46 paths it changes from `main` are exactly the union of its parents' paths; every one is byte-identical to the parent that changed it, except `web/package.json`, which carries both parents' dependency lines, and `pnpm-lock.yaml`, regenerated by `pnpm install` (the only conflict of the merge). So this file is the node's one addition.

**Cascade ritual**: `main` into `with/fuzd` and `with/pixi-js` first, then both into this node, in either order; a conflict here should only ever be the lockfile, resolved by taking either side and running `pnpm install`.
